Một vòng phát triển, ngay trong chat

Chọn source một lần. Mô tả thay đổi. Duyệt ZIP, Git backup và kế hoạch chạy. Tự kiểm thử rồi lặp lại.

Workspace trong phiên bản này là bản sao được Nopilot quản lý. Thư mục bạn chọn được đọc để nhập source theo .nopilotignore. Nopilot cập nhật bản sao đó; thư mục gốc và repository Git gốc của bạn được giữ nguyên. Sau khi nhập, dùng Mở source workspace để xem hoặc sửa đúng source đang làm việc. Git backup là repository local riêng của Nopilot, không push lên remote.

1. Chọn thư mục code và duyệt nhập

Nhấn Workspace dưới ô chat hoặc gõ /work rồi Tab để mở hộp chọn thư mục Windows. Chọn xong chỉ điền đường dẫn; bạn bấm Gửi để chuẩn bị card. Có thể tự nhập:

/workspace "C:\src\my-project"

Card cho biết thư mục gốc, source đích, số file/byte, danh sách file, mục bỏ qua và file ignore đang dùng. Bấm Nhập workspace và lưu Git backup để chấp thuận bản source đã đọc. Chưa có code dự án nào được cài hoặc chạy, chưa có source nào được gửi Copilot. Nếu không muốn dùng, bấm Hủy nhập.

Chọn thư mục chứa code thật, không chọn cả data directory của Nopilot. Mỗi conversation có project hiện tại riêng. Chọn thư mục khác và duyệt sẽ đổi project hiện tại của conversation đó.

2. Khai báo .nopilotignore

Đặt file UTF-8 .nopilotignore ở gốc dự án trước khi nhập. Nếu chưa có, dùng quy tắc mặc định của Nopilot và chép quy tắc đó vào workspace. File tự viết thay thế toàn bộ quy tắc mặc định, nên cần liệt kê cả môi trường, log và file riêng tư cần loại:

.git/
.venv/
venv/
node_modules/
__pycache__/
dist/
build/
logs/
screenshots/
*.log
*.zip
.env
.env.*
*.pem
data/private/
**/cache/
*.tmp
!important.tmp

Cú pháp tương tự .gitignore: *, **, dấu / neo tại gốc, / cuối dòng cho thư mục, ! để đưa file trở lại. Chỉ đọc file ignore ở gốc. Không tự đọc .gitignore. Symlink/junction bị bỏ qua; khi nhập workspace, .git luôn bị loại. Dùng card để kiểm tra source trước khi duyệt.

Giới hạn gửi project hiện tại: ZIP sau nén tối đa 1 MiB, tổng source 16 MiB, tối đa 2.000 file. Không phải giới hạn của toàn thư mục nếu các thư mục nặng đã được loại.

3. Yêu cầu sửa và lặp lại

Sau khi nhập workspace, gửi yêu cầu dưới đây. /iterate tự lấy source hiện tại trong conversation, nén theo ignore, tạo byte ZIP với tên .txt, upload một attachment và gửi yêu cầu theo contract:

/iterate Sửa dự án: thay URL chụp ảnh từ https://google.com thành https://facebook.com. Lưu screenshots/facebook.png, giữ Edge headless và dependencies hiện tại, bỏ previewUrl vì không chạy web server. Bổ sung test phù hợp và trả ZIP đầy đủ.

Không cần chọn lại path, tự nén hoặc tự đổi đuôi. Nội dung file TXT thực sự là ZIP nhị phân, không phải base64. Chat ghi các bước đóng gói, số file bị bỏ qua, upload và chờ model. Nếu project chưa có contract, prompt sẽ yêu cầu Copilot bổ sung nopilot.json, hướng dẫn CMD, ignore và commit message.

Khi ZIP sửa trở về

  1. Bridge tự tải file thật về artifacts của đúng conversation.
  2. Card Cập nhật và chạy hiện kế hoạch. Mở Xem kế hoạch và diff để xem file thêm/sửa/xóa, dependencies và commit message do Copilot viết; bạn có thể sửa message.
  3. Bấm chấp thuận: Nopilot lưu source hiện tại vào Git và checkpoint, áp dụng ZIP đầy đủ, commit bản mới, rồi thực hiện kế hoạch cài/chạy đã duyệt.
  4. Giữ venv nếu requirements và Python vẫn khớp; nếu đổi dependencies/runtime, tạo môi trường phù hợp rồi mới start. Cài lỗi thì không start.
  5. Bạn kiểm thử kết quả. Với web app, dùng Mở ứng dụng nếu contract khai báo URL loopback. Với script, mở log và artifacts.
ZIP là snapshot đầy đủ. File source không có trong ZIP mới sẽ bị xóa khi áp dụng. Venv và Git backup nằm ngoài source nên không bị giải nén ghi đè. Kế hoạch có hạn 15 phút; source hoặc runtime đổi thì cần xem lại kế hoạch. Mỗi lần chấp thuận chỉ áp dụng cho đúng bản source và lệnh đang hiện trên card.

Vòng tiếp theo, kèm log nếu cần

/upload "C:\logs\start-failed.log"

Chờ báo đã đính kèm, rồi gửi:

/iterate Hãy đọc log tôi vừa đính kèm, tìm nguyên nhân lỗi khởi động, sửa dự án và giữ các chức năng hiện có. Bổ sung test tái hiện lỗi và cập nhật README.

Log không tự được gửi Copilot. Bạn có thể dùng /up + Tab để chọn log qua dialog. Tối đa 3 attachment: project chiếm 1, còn tối đa 2 log. Nếu không cần log, gửi trực tiếp /iterate yêu cầu tiếp theo.

5. Contract để harness chạy mà không cần LLM điều khiển shell

Phiên bản hiện tại hỗ trợ Python trên Windows. /iterate và /develop gửi schema cho Copilot. Ví dụ project CLI có dependencies:

{
  "schemaVersion": 1,
  "name": "My Python project",
  "runtime": "python",
  "install": {"requirements": "requirements.txt", "timeoutSeconds": 300},
  "tasks": {
    "start": {"entrypoint": "main.py", "args": [], "timeoutSeconds": 120},
    "check": {"entrypoint": "check.py", "args": [], "timeoutSeconds": 60}
  }
}
  • requirements.txt chỉ chứa package được ghim package==version từ PyPI. Nếu chỉ dùng stdlib: install:null.
  • Entrypoint là file .py tương đối; args là mảng chuỗi. Không phải chuỗi lệnh shell, không dùng PowerShell.
  • stdin đóng: chương trình không được chờ input(). Dùng args cho CLI hoặc web app để nhập liệu.
  • Task check nên chạy độc lập, exit 0 khi pass. Đây là test model viết, bạn vẫn cần đánh giá chất lượng.
  • Task có timeout từ 1 đến 600 giây; hiện chưa có daemon vô hạn. Với web app chọn timeout đủ để bạn test, rồi Dừng.
  • Web app bind 127.0.0.1, không debug/reloader. Chỉ thêm previewUrl khi thật sự có server, ví dụ http://127.0.0.1:8899/. Nút mở URL không xác minh server đã sẵn sàng.
  • Mỗi ZIP sửa cần đủ source, nopilot.json, README cho CMD, .nopilotignore và NOPILOT_COMMIT_MESSAGE.txt. Không gửi .git/venv/secrets trong ZIP.

6. Khi có lỗi

Copilot chỉ trả đường dẫn sandbox dạng chữ

Gửi tin nhắn thường trong cùng conversation; chưa cần gửi lại source:

Bạn vừa trả đường dẫn sandbox dạng chữ nên tôi chưa tải được ZIP. Hãy dùng công cụ tạo file để tạo lại ZIP đầy đủ, kiểm tra file tồn tại và đính kèm file tải được. Trả link Markdown bấm được, giữ nopilot.json, README, .nopilotignore và NOPILOT_COMMIT_MESSAGE.txt. Nếu không tạo/đính kèm được, nói rõ; không bịa link.

Nopilot chỉ tạo card khi tải được ZIP thật. Nếu Copilot không còn source, gửi lại /iterate với yêu cầu. Không tự biến chữ sandbox thành link giả.

ZIP thiếu contract hoặc contract sai

Chọn Soạn yêu cầu bổ sung contract trên card lỗi, hoặc dùng /iterate yêu cầu bổ sung contract cho source hiện tại. Nopilot không đoán lệnh khởi động và không chạy shell theo văn bản model.

Cài dependencies hoặc chạy bị lỗi

Xem log local, chọn file log cần thiết bằng /upload, rồi /iterate mô tả kết quả mong muốn. Không gửi credentials hoặc dữ liệu không cần thiết. Cài lỗi sẽ dừng trước bước start.

Source thay đổi hoặc kế hoạch hết hạn

Dừng run nếu còn chạy, lập lại kế hoạch ZIP và đọc diff mới trước khi duyệt. Nếu bạn sửa tại source workspace, /iterate lấy đúng source đang có trên đĩa. Nếu sửa tại thư mục gốc, cần nhập workspace lại để lấy bản mới.

Checklist cho mỗi vòng

  1. Mô tả yêu cầu sửa và tiêu chí bạn sẽ kiểm thử.
  2. /iterate gửi source hiện tại; thêm log qua /upload khi cần.
  3. Đọc diff, đặc biệt file bị xóa và dependencies mới.
  4. Duyệt card cập nhật/cài/chạy.
  5. Tự kiểm thử, ghi rõ kết quả đạt/chưa đạt.
  6. Lặp lại trong cùng conversation để giữ workspace và venv.
